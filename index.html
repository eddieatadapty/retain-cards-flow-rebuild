Your ads × your flow

24 Meta ads, three promises. One onboarding for all of them.

Your Meta ads for Retain promised “why everyone deletes ChatGPT” in 10 of 24 ads, “how do you keep getting 1s?” in 7 and “I only found this out now” in 6, each one showing a photo of notes turning into flashcards and a plan to the exam. Yet every install meets the same 18 onboarding steps, a sign-up and a paywall with no ✕, and the flashcards only after it.

Flow Builder can open a different flow by the campaign an install came from, so the first screens keep that promise, and each ad is judged on the subscriptions it brings, not the installs.

Day 1

Pass the Meta campaign into Adapty

After a one-time SDK setup, the campaign each install came from (you already run Kochava) arrives as a user attribute and picks the flow at first open. No app release.

Week 1

One flow per promise

ChatGPT, top grades and “I only found this out now” each get their own first screens; installs from anywhere else keep today’s onboarding until you choose to split them.

Week 2

Judge each ad on what it earns

Each flow against today’s, measured on trials, purchases and what each install from that ad earns, so spend follows the promise that pays.

All three phones run the whole flow with the five ideas. None of these ads is running today: the last one stopped on 11 January 2026, and we found no Apple Ads for Retain in the US. The flows are ready for the next campaign. This layer carries no range: only a test per ad can give one.
